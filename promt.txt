# Project: CusIot — Electronics & Technology Store

Build a complete, responsive, modern e-commerce website named **CusIot**.

## 1. Business overview

CusIot is a small, student-started electronics and technology business based in Imphal, Manipur, India.

The website will initially operate as a product catalogue and WhatsApp-based ordering platform.

Customers can:
- Browse available products.
- Explore product categories.
- View product descriptions, images and prices.
- Select product quantities.
- Add products to their cart.
- Enter their delivery information.
- View their final order amount.
- Place orders through WhatsApp.

The owner will personally receive and manage all orders through WhatsApp.

There will be no customer registration, login system, online payment gateway or automated order-processing system in the initial version.

## 2. Technology stack

Use the following technologies:

- Frontend: React + TypeScript.
- Build tool: Vite.
- Styling: Tailwind CSS.
- Icons: Lucide React.
- Database: Supabase PostgreSQL.
- Product image storage: Supabase Storage.
- Hosting: Cloudflare Pages.
- Version control: GitHub.

Use a clean, component-based architecture.

Avoid unnecessary dependencies and complicated backend infrastructure.

## 3. Website design

Create a professional, clean and modern electronics-store design.

Design requirements:
- Minimalist interface.
- Professional typography.
- Consistent spacing.
- Clean product cards.
- Subtle animations.
- Smooth navigation.
- Responsive layout.
- Excellent mobile experience.
- Proper loading and error states.
- Accessible buttons and form fields.

Avoid:
- Excessive gradients.
- Excessive animations.
- Overly rounded components everywhere.
- Unnecessary glassmorphism.
- Generic AI-generated website aesthetics.
- Fake testimonials and fake customer reviews.

The website should look like a genuine small electronics business.

Include a light/dark theme if practical.

- Product images.
- Unit prices.
- Quantities.

- Subtotal.
- Delivery charges.
- Grand total.

Create a checkout form containing:

Customer details:
- Full name.
- House address / locality.
- City.
- State.
- PIN code.
- Optional additional delivery instructions.

Display the complete order summary.

Calculate:

Subtotal = Sum of product prices × quantities.

Grand Total = Subtotal + Delivery Charges.

Delivery charges must be configurable from the database.

Validate all required fields before generating an order message.

Do not require an account or registration.

## 7. Supabase database

Connect the application to Supabase.

Create the following database tables:

### products

Fields:
- id
- name
- slug
- description
- price
- stock_quantity
- image_url
- category_id
- is_featured
- is_published
- created_at
- updated_at

### categories

Fields:
- id
- name
- slug
- description
- image_url
- is_active
- created_at

### store_settings

Fields:
- id
- store_name
- whatsapp_number
- primary_email
- secondary_email
- delivery_charge
- free_delivery_threshold (optional)
- currency
- announcement
- updated_at

All product information, categories, stock quantities and store settings must be fetched dynamically from Supabase.

Do not hardcode products into React components.

### Database security

- Enable Row Level Security.
- Allow anonymous visitors to read published products and active categories.
- Allow public reading of necessary store settings.
- Do not allow anonymous visitors to insert, update or delete products.
- Do not allow public stock modification.
- Never expose the Supabase service-role key.
- Use only the public anon/publishable key in frontend configuration.
- Keep owner database management inside the Supabase dashboard.

The website must not include an unauthenticated admin interface.

## 8. Product image management

Use Supabase Storage.

Create a public product-image bucket.

The owner should be able to upload product images directly through the Supabase dashboard.

Store the image URL in the products table.

Optimize image display and use appropriate fallback images when an image is unavailable.

## 9. Inventory management

The owner will personally manage inventory through Supabase.

For example:

If a product has 15 units, the website displays 15 available units.

If the owner changes the quantity to 8 in Supabase, the website should reflect the new quantity.

Requirements:
- Display current stock.
- Hide or disable ordering for unavailable products.
- Prevent customers from selecting more than the displayed stock.
- Do not decrease inventory simply because someone adds an item to their cart.
- The owner will update inventory after personally confirming an order.
